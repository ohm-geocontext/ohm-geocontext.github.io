GeoContext turns a small JSON file in a public GitHub repo into an interactive, shareable map.

No fork No build No account No server of your own
See a live map Read the spec
The idea

A map is just a file in a repo.

Describe the map you want — basemap, data, layers — in one declarative file. GeoContext fetches it from your repo over a CDN and renders it. The repo stays the source of truth; the map updates when you push.

01

Drop a file

Commit a geocontext.json at the root of any public GitHub repo.

02

Add your data

Put GeoJSON or CSV next to it. Reference it with a bare relative path.

03

Open the map

Visit /<user>/<repo>/map. Share the link — that's it.

 geocontext.json
// at the root of your public repo
{
  "title": "My map",
  "center": [44.292, 13.975],
  "startzoom": 5,
  "background": "osm",
  "datasources": [
    { "name": "places",
      "type": "geojson+http+remote",
      "conf": { "source": "data/places.geojson" } }
  ],
  "layers": [
    { "name": "Places", "type": "features",
      "datasource": "places",
      "style": { "options": { "radius": 4,
        "fillColor": "#9448b7" } } }
  ]
}
Then open
…/<user>/<repo>/map

A full interactive map — pan, zoom, click a feature, read its detail. Push to the repo and the map follows as the CDN cache rolls over.

Two engines, three on-ramps

Write it, draw it, or export it — then tell it.

The format is plain JSON, so you can author it however suits you — by hand, from a desktop editor with a live preview, or straight out of QGIS. Then read the result as a map, or as a scrolling article that moves it.

GeoContext Front

ohm-geocontext/geocontext-front

The Angular + MapLibre/Leaflet renderer that reads any repo and draws the map at /<user>/<repo>/map. Plugin-driven: every basemap and data format is a small library you can extend.

Add a story.json next to your map and it becomes a longform article: prose scrolls in a column while the camera follows it, layers come and go, and the basemap crossfades underneath. A stories.json carries several readings of the one map.

Capabilities

More than dots on a map.

GeoContext composes basemaps, vector and tabular data, terrain, and even live streams — declaratively, with two rendering flavours under one format.

Your data

GeoJSON and CSV, inline or fetched. Tag CSV columns with gcx:lat / gcx:lon and rows become points.

Basemaps

OSM, CARTO, OpenFantasyMaps, raw XYZ, plus server-rendered wms-tiled and arcgis-image services.

Terrain & hillshade

Register a DEM and get hillshade — and optional 3D terrain on the MapLibre flavour. Ctrl-drag to tilt.

Live streams

The geomqtt layer subscribes to an MQTT broker and pushes incoming features onto the map in real time.

Static pages

Ship About / Sources / Methodology prose alongside the map with a geocontext-static.json registry.

CDN-delivered

Assets resolve through jsDelivr against your repo — short relative paths, cross-repo composition, no hosting to run.

Longform · new

And when the map has an argument to make.

A legend explains what the colours mean. It does not explain why the northern soundings matter, or what changed between 1976 and now. GeoContext Storybook reads a second small file next to your map and renders it as a scrolling article — the prose moves the camera, layers come and go, and the basemap crossfades underneath. One map can carry as many readings as it has arguments.

 story.json
// next to the geocontext.json it narrates
{
  "title": "A story on a map",
  "extends": "geocontext.json",
  "blocks": [
    { "title": "Down to one feature",
      "text": "The data decides where to look.",
      "camera": { "focus": { "datasource": "sites",
        "where": { "code": "D-04" } } },
      "layers": { "only": ["basin", "sites"] } },

    { "type": "tour", "datasource": "sites",
      "template": { "title": "{name}",
        "text": "{note}" } }
  ]
}
What each block can do

Move the camera — to coordinates, to a bounding box, or to whichever features match a property. Show, hide, dim or filter layers. Swap the basemap. Carry its own images, video and captions, or a full-bleed backdrop that hides the map entirely.

↓
And that last block

A tour writes itself from the data: one section per feature, framed on its own geometry, with {name} and {note} filled in from its properties. Add a row to the GeoJSON and the story grows a section.

 stories.json
// one map, several readings of it
{
  "kind": "geocontext-stories",
  "geocontext": "geocontext.json",
  "stories": [
    { "id": "excavation",
      "path": "stories/excavation.json",
      "title": "The excavation" },

    { "id": "drainage",
      "path": "stories/drainage.json",
      "title": "Draining the valley" },

    { "id": "next",
      "path": "stories/next.json",
      "draft": true }
  ]
}
One map, many readings

The excavation and the drainage. The 1976 survey and the 2019 one. Each narration is its own file over the same geocontext.json; the index lists them, and every story carries a switcher to its siblings. A draft stays in the repo and out of the reader's way.

↓
And back again

A story links to the map it argues about; the map links to the stories written about it. Neither app is told about the other's content — both simply read the repository.
